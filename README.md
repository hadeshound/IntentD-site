# IntentD — публичный сайт

Astro 5 · TypeScript · Tailwind CSS · Zod. Разворачивается на Cloudflare Pages.

## Запуск

```bash
cp .env.example .env
npm install
npm run dev       # http://localhost:4321
```

Требуется работающий портал на `http://localhost:8080` (см. `../portal`).
Без него страницы всё равно отрисуются: каталог тарифов подменяется локальной
копией сид-данных, а формы покажут ошибку сети.

## Команды

```bash
npm run dev        # дев-сервер, http://localhost:4321
npm run build      # astro check + сборка в dist/
npm run preview    # прогон собранной сборки в воркере (wrangler)
npm run typecheck  # astro check без сборки
```

## Переменные окружения

Все переменные названы `PUBLIC_*`: Astro отдаёт браузеру только этот префикс,
и каждое из этих значений действительно нужно на клиенте.

| Переменная | Назначение |
|---|---|
| `PUBLIC_API_BASE_URL` | база API портала, например `https://api.intentd.io/v1` |
| `PUBLIC_SITE_URL` | канонический origin сайта: метаданные, sitemap, robots |
| `PUBLIC_DASHBOARD_URL` | origin кабинета: ссылки «Войти» и «Кабинет» |

## Деплой (Cloudflare Pages)

| Параметр | Значение |
|---|---|
| Build command | `npm run build` |
| Output directory | `dist` |
| Node version | 20 или новее |
| Переменные | `PUBLIC_*` из таблицы выше, в настройках проекта |

Заголовки безопасности лежат в `public/_headers` — Cloudflare Pages читает этот
файл сам. `Content-Security-Policy` там намеренно нет: она настраивается на
edge вместе с report-эндпоинтом и стратегией nonce.

## Что рендерится статически, а что нет

`output: 'static'` — в Astro 5 это и есть режим «гибрид»: страница
предрендерится, если не отказалась явно. Отказываются только те, что читали
`searchParams` на сервере в Next-версии:

| Маршрут | Режим | Почему |
|---|---|---|
| `/auth/login`, `/auth/register`, `/auth/reset-password`, `/checkout` | SSR | читают `?redirect`, `?plan`, `?role`, `?token` на сервере |
| всё остальное | предрендер | HTML собирается на сборке |

Каталог тарифов читается один раз, во время сборки. `revalidate = 300` в
Next-версии делал то же самое; здесь изменение цены подхватывает следующий
деплой, который Cloudflare Pages умеет запускать по webhook.

## Острова

Интерактивность вынесена в React-острова (`client:load`): формы обращения,
входа, регистрации, восстановления и сброса пароля, панель оформления заявки.
Всё остальное — статический HTML: секции лендинга, тарифы, документация,
юридические документы.

Остальная интерактивность — обычные скрипты в `.astro`, без React: шапка
(скролл и мобильное меню), аккордеон, копирование кода, индикатор статуса и
появление блоков при скролле. Поэтому `/pricing` и документация грузят меньше
килобайта JavaScript.

### Сессия без React-контекста

`AuthProvider` из Next-версии заменён модульным хранилищем
`lib/auth/session.ts`. Причина: в Astro нет одного React-дерева — каждый остров
гидратируется сам по себе, и провайдер внутри одного невидим для другого. Два
острова с двумя провайдерами означали бы два молчаливых обновления сессии,
соревнующихся за один ротируемый refresh-токен.

Модульное хранилище решает это: острова одной страницы делят один экземпляр, а
поскольку это обычный TypeScript, шапка и карточки тарифов подписываются на него
из `<script>` — без React на страницах, где форм нет. `useAuth()` остался
React-обёрткой над тем же хранилищем.

Свойства безопасности не изменились: токен доступа по-прежнему живёт только в
памяти вкладки (`lib/api/client.ts`), refresh-токен — в HttpOnly-cookie, которую
этот код прочитать не может. При 401 на защищённом запросе клиент один раз
молча обновляет сессию и повторяет исходный запрос.

### Защита /checkout

Проверка сессии остаётся клиентской (`components/auth/AuthGuard.tsx`).
Серверная проверка cookie невозможна: refresh-cookie выставлена доменом API и
на этот origin не приходит. Страница показывает ожидание, пока молчаливое
обновление не ответит, затем либо отдаёт содержимое, либо заменяет запись в
истории страницей входа.

## Дизайн-система

Палитра и типографика заданы в `tailwind.config.ts`; дефолтная палитра
Tailwind не используется.

| Роль | Значение |
|---|---|
| Фон | `#0B0F17` (`void`) |
| Слои карточек | `#111827`, `#1F2937` (`carbon-800/700`) |
| Акцент | `#10B981` / `#059669` (`mint-500/600`) |
| Свечение | `#6366F1` (`violet-500`) — только ambient glow, не заливка кнопок |
| Заголовки | `#FFFFFF` (`ink`) |
| Текст | `#9CA3AF` (`ink-muted`) |
| Границы | `rgba(255,255,255,0.08)` (`hairline`) |

Шрифты: **Golos Text** (заголовки), **Manrope** (текст), **JetBrains Mono**
(код и лейблы) — self-hosted через `@fontsource-variable`, с разбиением по
`unicode-range`, поэтому читатель скачивает только нужные начертания. Ни Syne,
ни Space Grotesk, ни Plus Jakarta Sans, ни Clash Display не содержат кириллицы,
а весь контент русский, поэтому пары из ТЗ дали бы системный фолбэк.

Приёмы вёрстки: асимметричные сетки 7/5 и 6/6 со смещением по вертикали,
перекрытие слоёв, крупная типографика с `clamp()`, тонкие границы 1px,
glassmorphism на шапке и акцентных карточках, размытые цветовые пятна за
ключевыми блоками, hover как подъём на 2px плюс потепление границы.

Анимируются только `transform` и `opacity`. Появление блоков при скролле —
один IntersectionObserver на страницу (скрипт в `BaseLayout.astro`), срабатывает
один раз. `prefers-reduced-motion` отключает и дрейф свечений, и пульсацию
индикатора, и появление блоков.

## Доступность

Семантические заголовки и списки, `aria-expanded` на аккордеоне и мобильном
меню, `aria-describedby` от поля к его ошибке, `role="alert"` на сообщениях
формы, видимое кольцо фокуса на тёмном фоне, ловушка фокуса и возврат фокуса в
модальном окне, skip-link первым в порядке табуляции, настоящие `<table>` с
`scope` в матрице тарифов и схеме данных.

## Проверки

```bash
npm run typecheck
npm run build
```

`astro check` проходит без ошибок и предупреждений; production-сборка
генерирует 12 предрендеренных маршрутов и воркер для четырёх SSR-страниц.

`npm run preview` поднимает `wrangler pages dev dist`: адаптер Cloudflare не
поддерживает `astro preview`, потому что SSR-страницы должны выполняться в
воркере, а не в Node.
